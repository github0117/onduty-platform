# 完整能力清单

本文件保留平台的完整功能细节；README 只保留核心能力概览。

## 电商运营与内容生产

- 商品与 SKU 管理。
- 电商规则知识库和引用追踪。
- 受限宣传语检查与人工接管。
- 商品图片、AI 主图、视频和字幕素材。
- 分镜批次隔离和旧素材归档。
- Outbox + Celery 异步视频渲染。
- 缓慢推近、淡入淡出和字幕时间线。
- 标题、卖点、详情和标签的人工编辑与复审。
- 发布成功率、平均上架耗时、人工介入率和视频成功率。
- ZIP 上架资料包导出。
- 电商审计、素材生命周期和成本记录。
- 电商商品按品类档案动态检查必填属性和合规宣传语。
- 千问 DashScope OpenAI 兼容文案生成接口。
- 低成本 `z-image-turbo` 商品图和分镜生成。
- `qwen-vl-ocr` 检查主图和分镜中的多余文字。
- `qwen3-tts-flash` / `Cherry` 生成中文分镜旁白并混入视频。
- Noto Sans CJK 字幕烧录和 48kHz AAC 响度标准化。
- 支持上传真实 BGM、循环裁剪和配音自动闪避。
- CSV 商品模板下载、逐行校验、错误报告和批量创建商品。
- 一次最多选择 10 个商品批量生成上架任务，支持逐项状态、失败隔离和任务关联。
- 运行与审计支持管理员检查并恢复固定演示数据；恢复只作用于 `bu_demo`，
  需要显式确认头，提交后在后台执行并通过任务状态轮询结果；恢复幂等、可重复执行、
  不删除手工创建的业务数据，并阻止并发重复运行。

## 知识库与 RAG

- 知识空间创建与文档动态归类，支持按平台、品类和工作流组织知识。
- 文档解析覆盖 txt、Markdown、HTML、DOCX 和 PDF；保留标题层级、列表和表格
  结构，清洗页眉页脚、页码、零宽字符和硬换行，解析结果按结构化块保存，
  供后续分块与重建索引复用。
- 结构化分块（`KNOWLEDGE_CHUNKING_VERSION=v2`，默认关闭）按章节组织，表格
  不拆行、单独成块，块元数据记录章节路径与块类型；关闭时沿用字符窗口分块。
- 重建索引（`POST /knowledge/reindex`）按业务单元或文档重建向量，不依赖对象
  存储：按 `(embedding_model, chunking_version)` 判定是否已是最新，重复请求复用
  未完成任务，失败按次重试并在 3 次后进入死信；任务状态可在
  `GET /knowledge/reindex-jobs` 查询，全程留存审计。
- 嵌入不再静默回退：关闭 `embedding_fallback_to_local` 时远端失败直接报错、
  版本不落库；开启时按真实使用的本地模型名与 `embedding_fallback_used` 标记
  写入，避免向量空间混用。`/metrics/rag` 增加 `embedding_model`、
  `embedding_quality` 与 `reindex_pending_versions`，模型切换后未重建的版本
  可被观测。
- 语义嵌入是推荐配置（`.env.example` 默认指向 DashScope `text-embedding-v3`）。
  未配置 `EMBEDDING_BASE_URL`/`EMBEDDING_API_KEY` 时不会每次请求都去撞远端，
  而是直接使用本地 `local-hash-256` 演示模式：`embedding_quality=demo`，
  运营页显示橙色提示“检索质量不代表语义检索水平”；自托管无鉴权端点需显式
  设置 `EMBEDDING_ALLOW_EMPTY_API_KEY=true`。配置密钥后必须重建索引。
- 检索结果是给模型看的上下文，不是搜索结果页：同一文档内近乎重复的段落会被
  去重（完全相同或包含且长度比 ≥ 0.8），总字符数受
  `KNOWLEDGE_CONTEXT_MAX_CHARS`（默认 5000，0 为不限）约束，避免重复段落
  占用 token 和引用位。可用 `KNOWLEDGE_CONTEXT_PRUNE_ENABLED=false` 关闭。
- 评测用例支持段落级期望（`expected_passages`：文档 ID + 原文片段）。运行评测
  时按当前生效版本的 chunk 文本解析出 chunk ID，因此重建索引、切换分块版本都不会
  让用例失效；段落存在时优先于显式 `expected_chunk_ids`。段落文本在语料中找不到
  时，该用例判失败并在结果里给出 `unresolved_passages`，整次运行的 verdict 强制
  为 FAIL（配置错误不能伪装成检索失败）。
- 知识运营页可直接新建段落级期望：选择文档、填写原文片段，最多 20 条，可逐条
  删除；评测案例列表显示“N 段原文”。最近一次评测卡片展示
  `avg_context_chars` / `avg_context_tokens`，并把无法解析的段落以红色列出
  （原文未找到 / 文档未索引），配置错误在页面上即可定位。
- 重建索引会更换 chunk 主键，纯 chunk 引用的旧用例同步重映射：按文本完全
  一致 → 旧块并入单个新块 → 旧块被拆成多个新块（取序号最小者）逐级匹配，
  同业务单元内去重改写。HOLDOUT 是冻结集，只跟随**文本完全一致**的换主键，
  合并/拆分匹配只用于 TUNING。带段落期望的用例不参与重映射，也不计入
  `stale_evaluation_chunk_refs`（它们的 chunk 引用只是缓存）。无法确定的引用
  保持原样并计入 `/metrics/rag` 的 `stale_evaluation_chunk_refs`，让评测显式
  失败而不是悄悄弱化门禁；运营页会以红色提示展示该数量。
- 混合检索（`KNOWLEDGE_RETRIEVAL_MODE=hybrid`，默认 `dense`）：向量召回与
  PostgreSQL 全文召回（`to_tsvector('simple')` + `ts_rank_cd`，表达式 GIN
  索引）各取候选，用 RRF 融合后再重排，兼顾语义召回与型号、单号等精确词面
  命中。SQLite 与未回填的历史 chunk 自动退化为向量召回，`/knowledge/search`
  返回实际生效的 `retrieval_mode`，未回填版本计入 `reindex_pending_versions`。
- 远端 cross-encoder 重排（`KNOWLEDGE_RERANK_PROVIDER=external`）：按候选数与
  最高向量分决定是否调用远端 `POST /rerank`，单次最多 30 条、超时 3s；超时或
  5xx 自动回退本地重排并在 `ticket_worker_rag_rerank_fallbacks_total` 计数，
  检索不会因重排失败而失败；关闭回退时返回 `503 RERANK_UNAVAILABLE`。
- 多轮查询消解（`KNOWLEDGE_QUERY_CONTEXT_ENABLED`，默认开）：客服跟随问
  （“那退款呢”）用最近买家轮次解析指代，优先替换为型号/订单号，原始问题仍
  参与 RRF；LLM 多查询默认关闭，仅在最高分低于阈值时触发，失败静默回退并
  计入 `ticket_worker_rag_query_rewrite_fallbacks_total`。
- 数字员工可绑定多个知识空间，检索与工作流执行均校验空间授权。
- 商品新增或变化后自动生成静态商品知识卡，使用内容哈希避免重复索引。
- 知识评测中心支持召回率、MRR、无答案检测和失败修复任务。
- 评测案例分为 TUNING（调参集）和 HOLDOUT（留出集）：调参集可改可删，留出集创建后
  接口级冻结（`409 HOLDOUT_CASE_IMMUTABLE`），只能按业务单元 + 数据集过滤查询；
  既有案例在迁移时回填为 HOLDOUT，既有运行回填为 TUNING。
- 评测指标同时给出 chunk 级和文档级 Recall@K / MRR，并统计 context precision、
  平均上下文字符数与估算 token（`avg_context_chars` / `avg_context_tokens`）
  和负例文档违规率；`/knowledge/evaluation-runs` 的每次运行也返回这两个均值
  （由逐用例 `context_chars` 推导，早于该字段的旧运行为 `null`）。每次运行写入
  `baseline_json`（数据集、top_k、嵌入模型与维度、分块版本、检索模式、RRF k、
  重排器、查询上下文/改写开关、阈值）。
- 关键知识空间可启用发布门禁：门禁只跑已启用的 HOLDOUT 案例，没有可用留出集时
  返回 `409 KNOWLEDGE_EVALUATION_HOLDOUT_EMPTY`；评测失败自动回滚候选版本、
  生成修复任务并返回 `409 KNOWLEDGE_EVALUATION_GATE_FAILED`。
- 修复任务回归验证沿用来源评测运行的数据集；停用知识空间会联动停用其留出集案例，
  此时只允许 `{"enabled": true}` 的恢复补丁，其余修改仍返回 409。
- 线上正负反馈可关联知识、员工和工单，负反馈自动生成修复任务。

## 客服对话与自动回复

- 电商售前和售后独立分类路由，售后订单/退款问题强制人工。
- 知识有引用且校验通过的 R0 售前问题可自动回复，无需逐会话人工确认。
- 自动回复受置信度、敏感动作、工具权限和策略审批共同约束；模型 fallback、
  引用声明未校验或校验不通过时一律转人工。
- 客服会话沙盒支持提问、引用、人工改写、点踩和自动修复任务。
- 每轮对话是独立的运行时事务：`conversation_turns` 带 `correlation_id`、
  乐观锁 `version`、`attempt_count` 和 worker 租约，状态只能沿合法边迁移，
  非法跳转返回 `409 INVALID_TURN_TRANSITION`；每次迁移写入
  `conversation_turn_events`，可通过
  `GET /api/v1/customer-service/conversations/{conversation_id}/turns/{turn_id}/events`
  查看这一轮从排队、认领、上下文组装到完成/失败的全过程。
- 租约过期的轮次由 Celery Beat 每 30 秒回收并重新派发，超过
  `CONVERSATION_TURN_MAX_ATTEMPTS` 标记 `FAILED_TERMINAL`；运维也可调用
  `POST /api/v1/customer-service/turns/reclaim` 手动触发（需要
  `operations.manage`）。
- 多轮上下文按固定顺序装配：会话记忆 → 最近一次交接摘要 → 预算内的消息窗口 →
  当前消息。装配结果写入 `conversation_turns.context_json` 并附在
  `CONTEXT_ASSEMBLED` 事件里，可核对这一轮到底看到了哪几条、是否被截断；
  消息窗口按“买家／客服（员工名）”标注，`customer_messages.turn_id` 指向产生
  该条消息的轮次。
- 会话记忆是结构化 v2（`facts` 带 `source_turn_id`、待办、承诺、悬而未决的问题、
  滚动摘要与 `summarized_through_sequence`）；读到旧 v1 记忆时惰性升级并回写，
  升级不改变历史内容。
- 同一会话的轮次串行执行：后到的轮次保持 `PENDING` 且持有效租约，等上一轮结束
  后自动接力；客户端可传 `client_message_id`，同键重复提交返回原轮次并标记
  `replayed=true`，不会写出第二条买家消息。两条消息在同一瞬间到达时，只有一次
  建单（`TicketService.create(commit=False)` 让会话行锁贯穿整个请求），两条消息
  各自成为一个轮次。
- 上下文窗口是因果的：只取“本消息之前”的消息。买家在上一轮还没答完时又发了下一条，
  那条不会提前出现在上一轮的上下文里。
- 员工交接落库到 `conversation_handoffs`（自动改路由 `AUTO_REROUTE` /
  人工切换 `OPERATOR_SWITCH`），含确定性摘要（确认事实、待办、承诺、上一轮回答
  与引用、未确认项），下一轮装配直接读取该摘要；主管可在客服会话页选择员工并
  点“交接”（`POST /api/v1/customer-service/conversations/{conversation_id}/employee`，
  需要 `operations.manage`），成功后消息上方出现“由 A 交接给 B”横幅。
  交接目标必须是同一业务单元、同一领域的在岗员工：跨单元 400
  `HANDOFF_EMPLOYEE_UNIT_MISMATCH`，跨领域 409 `EMPLOYEE_DOMAIN_MISMATCH`
  （客服会话不能交给 HR 或运营员工）。
- 答案依据判定统一走 `grounding_status_from_claims`：只有所有被引用声明都
  校验为 `supported` 才标记 `GROUNDED`；MCP 只读工具结果以
  `direct_tool_result` 计为已支持，抽取式知识回答必须通过声明校验器，未校验
  一律 `UNVERIFIED`。
- 工作台可从会话自动识别订单，展示客户、物流、售后和收货地址上下文。
- 收货地址修改走 R2 人工审批，支持重复申请幂等、超时结果未知和只读对账；
  沙箱提供正常、超时和明确拒绝三种模式。
- 页头区分“当前操作身份”和“这段对话双方”，身份菜单显示岗位职责；客服聊天在
  平板和手机宽度自动改为上下布局。
- 客服对话进入人工工作台时保留当前会话 ID，往返两个页面仍显示同一条会话；
  人工回复成功后消息立即出现在主对话窗口。
- 运营页“业务价值（近 N 天）”按业务单元与时间窗（7/30/90 天）聚合草稿审核结果与
  模型成本：采纳率只统计人工已审核草稿（自动通过、待审核单独计数），并给出采纳后
  修改率、单会话模型成本和单采纳草稿成本；对应接口
  `GET /api/v1/customer-service/value-metrics` 需要 `operations.view` 能力。
- 知识库“答案抽检”页（`/knowledge/answer-quality`）对已采纳草稿做人工抽检：
  记录正确/部分正确/错误与幻觉标记，输出抽检覆盖率、正确率和幻觉率，
  同一草稿重复提交覆盖旧结论；对应接口
  `GET /api/v1/knowledge/answer-evaluations/summary`、
  `GET .../samples`（需要 `operations.view`）和
  `POST /api/v1/knowledge/answer-evaluations`（需要 `knowledge.write`）。
- 抽检结论为错误或标记幻觉时进入“最近未通过抽检”清单，可通过
  `POST /api/v1/knowledge/answer-evaluations/{draft_id}/repair-task` 生成（或复用）
  知识修复任务，任务与抽检结论相互关联；仅失败结论可开任务，重复请求幂等。
  “修复与反馈”页的“知识缺口 Top 10”通过 `GET /api/v1/knowledge/gaps` 合并
  待办修复任务、负反馈聚类和窗口内未生成任务的抽检失败，按次数与优先级排序。

## 业务入口、员工复用与前端视图

- 演示种子包含 316 不锈钢保温杯商品知识，AI 商品回答具备可检索依据。
- 买家对话页只展示模拟买家视角；内部客服、主管和平台岗位不在客户页面切换。
- 业务入口绑定数字员工池，聊天会话由入口进入并在绑定员工中自动分派。
- 员工保留一份能力配置，可同时加入多个业务入口；HR 入职员工同时服务企业服务台
  和内部 HR 入口，员工名单、路由页和快照会标记“跨入口复用”。
- 员工名单和客服对话里的员工姓名可打开同一份只读能力快照，展示 Skill、知识空间、
  MCP 授权和所在入口；名单支持 `?employee=<id>` 深链，方便从对话跳到平台配置。
- 员工路由页面支持维护入口的默认、专业和兜底员工，再配置意图派单规则。
- 电商运营入口绑定商品上架、视觉内容和运营主管数字员工；上架任务与素材显示负责员工。
- 页头不再常驻六角色切换，买家页固定买家视角；业务、管理和平台视角统一切换入口
  收进“5 步演示”设置。
- 买家消息和人工回复点击后立即显示发送中状态，失败恢复原文；切换工作台会话先用
  列表快照立绘并预取详情，避免演示时出现空白或按钮无响应。
- 客服看板展示 R0–R3 四级风险分布，待接管队列与风险/优先级联动。
- 接管后可直接发送人工回复，并可发送同时标记解决和释放客服名额。
- 会话列表可按等待审核、等待人工、我负责和已处理完成切换。
- 会话历史按聊天记录展示，可切换当前工单与全部历史。
- 接管会话后可生成千问人工回复建议，展示知识引用并要求人工确认后发送。
- 人工回复可按专业、简洁或亲和风格交给千问优化，不会自动改写数字承诺。
- 客服回复建议使用 LangGraph 执行 Skill 路由、知识检索和千问生成，并返回节点 Trace。

## MCP 工具与审批闭环

- Skill 支持数据库配置、版本更新、启停和员工绑定，LangGraph 运行时动态读取。
- MCP 连接器支持注册、Streamable HTTP 健康检查、真实工具发现和员工级授权。
- 已真实验证公开 DeepWiki MCP：发现 3 个只读工具，并成功查询
  `modelcontextprotocol/python-sdk` 的仓库文档结构；该能力用于研发支持员工，
  不代表已经接入企业订单、工单或物流生产系统。
- 研发支持员工已加入企业服务台入口，LangGraph 能规划并执行
  `deepwiki-public.read_wiki_structure` 或 `read_wiki_contents`，ToolCall 成功并
  生成 `source_type=mcp` 引用。
- 公开仓库文档查询按低风险技术文档问题自动处理，不再直接弹人工接管；私有仓库、
  密钥和访问令牌请求仍按安全风险转人工。
- 固定 DeepWiki 文档问题按任务选择只读工具：目录使用 `read_wiki_structure`，
  模块/职责/依赖使用 `read_wiki_contents` 并整理中文摘要，实测约 4–7 秒。
- 技术知识检索会过滤无关 IT、商品和通用制度文档；缺少工具或资料时明确返回
  证据缺口，不再回退到“产品配置支持组”模板。
- “你是谁、能做什么、帮我看看”等身份和澄清问题直接回复，不创建错误工单；
  “它有哪些依赖关系”等追问会继承上一轮公开仓库上下文。
- 完整 GitHub URL 会规范化为 `owner/repo` 并写入会话记忆；后续询问“这个仓库的
  文档结构”时复用同一仓库和工单，不要求重复提供地址。
- LangGraph 可按会话意图规划 MCP 工具；只读工具结果作为实时引用进入千问回复。
- MCP 调用记录工具、参数摘要、耗时、结果和错误；敏感信息统一脱敏。
- 可写 MCP 工具会生成持久化审批单，不会在回复建议阶段直接执行。
- 审批仅允许主管或管理员处理，申请人与审批人必须是不同账号。
- 审批通过后只执行一次，重复请求不会再次触达外部写接口。
- MCP 工具参数按输入 Schema 校验，缺失必填字段时拒绝创建审批。
- 写操作增加确定性策略：校验工单分类、风险、退款金额和硬上限，不依赖模型自行放行。
- 退款金额超过主管阈值时自动提升为管理员审批，超过平台硬上限直接拒绝。
- 外部写调用失败自动生成事故单，区分明确拒绝和执行结果不确定，禁止自动重试。
- 页面支持事故确认、处理人和关闭结论，要求先在订单/资金系统核对真实结果。
- 事故可调用绑定的只读 MCP 工具自动对账，并将真实外部结果写入事故记录。
- Celery Beat 默认每 120 秒对最多 20 个执行结果不确定的事故执行只读对账。
- 补偿动作必须使用 `reverse` 或 `compensate` 工具，并创建新的管理员审批。
- 补偿成功后才允许把“已执行但结果错误”的事故关闭。
- 客服页面提供 MCP 写操作审批列表、审计参数、审批意见和执行结果。

## 外部连接中心（邮件渠道与只读业务系统）

- 统一的连接器注册表：`connector_type=email` 或 `http_json`，方向支持
  `INBOUND` / `OUTBOUND` / `BIDIRECTIONAL`，按业务单元隔离并带版本号。
- 邮件渠道使用真实 IMAP 拉取未读邮件、SMTP 回信；按 `References → In-Reply-To →
  Message-ID` 归并会话，出站 `Message-ID`、`In-Reply-To`、`References` 保持线程。
- Celery Beat 每 60 秒轮询启用的邮件连接器；同一 `Message-ID` 由唯一约束
  `(connector_id, external_message_id)` 保证只入库一次。
- 入站消息先落库再处理，未绑定业务入口、连接器停用或方向不允许时保留失败记录并
  返回明确错误，不会静默丢信。
- 处理成功的邮件会创建/复用客服会话、工单和对话轮次；只有数字员工回答完成且工单
  完成时才自动回信，出站回复通过 Outbox 重试，失败保留错误并支持人工重试。
- 人工客服在会话工作台发送的回复会自动桥接到邮件连接器（幂等键按会话与回复序号
  生成），外部会话与站内会话共用同一套工单和审计。
- 只读 HTTP JSON 连接器支持健康检查与 GET 查询，4xx 明确拒绝、429/5xx 标记可重试；
  写操作仍只走既有 MCP 审批链路。
- Webhook 入站按 `X-Connector-Signature`（`sha256=<hex>` HMAC）验签，未配置或错误
  签名分别返回 503/401；webhook 路由不依赖 OIDC，避免身份网关阻断签名流量。
- 密钥只保存环境变量名（`secret_ref`），值从进程环境或 `CONNECTOR_SECRETS_JSON`
  读取；创建/更新接口递归拒绝包含 `password`、`token`、`api_key` 等字段的配置。
- 管理页面位于“员工与能力 · 外部连接（邮件 / MCP）”，支持列表、创建、启停、健康
  检查、业务入口绑定、最近消息和失败重试；只读角色只能查看，写入口按
  `mcp.connectors.write` 隐藏。

## 客服视图、工作台与服务席位

- 电商客服默认进入“聊天演示”，首屏只有对话窗口、买家输入框和简短处理说明。
- 支持商品咨询、物流查询、退款审批快捷提问；买家气泡、数字员工回答和待确认建议
  都以对话气泡呈现，输入框支持 Enter 发送、Shift+Enter 换行。
- 商品咨询使用预置保温杯客服岗位和商品知识，默认带出当前商品；对话结束后可直接继续追问。
- 建议回复尚未发送时会显示为虚线“建议回复”气泡并附知识引用，高风险时明确提示转人工。
- 服务工作台保留会话列表、自动派单、人工接管、SLA、审批、事故、Trace 和 MCP 管理。
- 支持“聊天演示 / 服务工作台 / 管理员视图”三种视图，指标、审批和事故按角色收起。
- 已移除全局“业务视图 / 技术视图”切换。侧边栏只保留“Agent 演示”和“平台管理”
  两个一级分组；客服、员工、模型等二级页面使用页内横向导航。
- 完整客服工作台收敛为三栏：左侧会话列表、中间对话和审核气泡、右侧接管/审核辅助/业务信息；
  审批、事故和系统治理留在管理员视图。
- 选中会话后自动生成 AI 回复草稿，新买家消息到达后自动刷新，无需逐次点击生成。
- 未接管会话也可预览 AI 草稿；发送消息仍要求先接管，避免多人同时回复。
- 工单分类和风险评估完成后自动派单，按业务单元、技能、风险权限和负载选择坐席。
- 普通坐席直接看到“我的会话”；公共待接管队列仅处理无可用坐席等兜底情况。
- Celery Beat 每 10 秒兜底扫描自动派单，“主管立即补派”仅作为人工补偿操作。
- 自动补派返回分配原因和候选明细，页面可查看技能、风险权限、负载、并发上限和排除原因。
- 在线客服、队列、补派、告警和离线回收均按业务单元隔离，跨租户心跳返回 403。
- 数字员工中心默认使用业务配置视图，技术参数收进管理员高级配置。
- 支持企业服务台、售前、售后、物流和 HR 入职五个岗位模板，自动生成员工编码、
  工作流和默认权限。
- 模板页通过具体模板卡的“使用这个模板”创建员工，不再提供会默认选择首个模板的
  重复顶部入口。
- 已发布自定义模板会进入员工创建选择器，并标记为“自定义已发布”。
- 数字员工配置支持 Manifest、发布版本和更新后自动生成新修订。
- 每名数字员工可配置角色提示词，手动新建和从模板创建员工时也可直接填写；提示词
  随配置版本保存，并注入回复建议、工单草稿和主管子任务生成。它只调整角色、语气和
  服务边界，不能覆盖安全约束、知识事实和人工审批规则。演示数据为各岗位员工预置了
  可查看和修改的提示词样例。

## 员工路由、主管编排与生命周期

- 会话可以不指定数字员工，系统按关键词、同义词和本地语义相似度自动选择专业员工。
- 员工归属是会话属性：后续消息默认由同一员工继续，单条相似消息不会换人；
  改派需要明确要求、能力缺口、上一张工单完成或连续多轮同主题。
- 自动改派受分数差、连续轮次、冷却轮次和单会话上限约束，原因码写入交接记录
  （`EXPLICIT_REQUEST / CAPABILITY_GAP / TOPIC_CHANGED / SUSTAINED_TOPIC /
  ENTRY_SCOPE_CHANGED`）。
- 主管手动切换会锁定会话（`employee_source=MANUAL`），此入口路由不再覆盖。
- 来自业务入口的会话，手动切换只能转给该入口内已启用的员工，否则返回
  409 `HANDOFF_EMPLOYEE_OUTSIDE_ENTRY`；没有入口的会话仍按领域校验。
- 领域包（`DOMAIN_PACKS_DIR`）声明领域与工作流：内置 `customer_service`、
  `human_resources` 两个包，新增方向只需增加 TOML 文件并指向现有流程类，
  员工创建时 `domain` 由工作流所属的包决定，不再按 key 前缀猜测。
- 领域包在 API、Celery worker 和 beat 启动时完成校验：重复 key、未知字段、
  handler 无法导入都会让进程启动失败，而不是落到第一张工单上。
- 每次路由记录候选员工、主体/背景/同义词命中、关键词分、语义分、综合分、置信度、
  排除原因和最终选择；分数接近时提示人工确认，没有可靠命中时进入低置信度兜底。
- 客服主管数字员工可把复杂目标拆成分步任务，并自动分配售后、物流、主管等员工。
- 主管任务图保存每个子任务的负责人、指令、状态、路由原因、置信度和候选解释；
  子任务主体与完整任务背景隔离，避免退款等背景词覆盖物流等主体能力。
- 主管任务可进入真实执行：专业员工按各自知识库、Skill 和模型产出结果。
- 子任务支持 RUNNING / SUCCEEDED / FAILED、失败重试和主管结果汇总。
- 主管子任务可调用专业员工已授权的只读 MCP 工具，写工具不会进入子任务候选集。
- 工具调用写入子任务 `tool_calls`，实时结果以 `source_type=mcp` 进入结构化引用。
- 后续主管和风险步骤会继承前序专业员工结果，并以 `workflow_step` 引用保留证据链。
- 主管任务卡可展开每个子任务的 ToolCall、耗时、错误和 MCP/前序步骤引用。
- 主管规划后检查每个步骤的员工 Manifest 能力；缺失时返回 `DRAFT_ONLY` 员工草案，
  展示建议模板、能力、Skill 和工具，并阻止任务交给兜底员工执行。
- 支持解析目标中“XX能力：说明”的能力清单；财务、仓储等无现成模板的能力也会生成草案。
- 主管规划同时检查员工状态、工具白名单、知识库、Skill 和实时 MCP 就绪度。
- 能力缺口、资源检查和评估时间以快照保存；员工后续变更不会改写历史规划结果。
- 工具权限或员工状态阻塞时拒绝执行；知识、Skill、MCP 缺失时标记降级并提示人工补证。
- 员工草案支持独立落档、管理员评审、试用员工、资源评测、正式发布和回滚停用。
- 试用员工不参与自动路由；评测通过后才能发布，发布和回滚均生成员工配置修订。
- 被拒绝的草案支持重新打开；提前发布、重复发布、重复回滚和非法状态转换会被拒绝。
- 能力缺口会识别已有草案，重复生成时直接显示状态和草案入口，不会一直停留在加载状态。
- 已验证的员工草案可沉淀为数据库化岗位模板，经批准和发布后用于创建更多员工。
- 自定义模板支持模板草案、批准、拒绝、发布和停用，停用后不能继续创建员工。
- 岗位模板编辑页可选择知识空间、按空间限定工作流和适用范围（受众、组织、区域、
  商品），并逐项选择 MCP 工具；已有绑定保留原授权和未知 scope 字段，新增 MCP
  连接默认只授予只读工具。员工配置页同样支持逐项工具授权和写审批开关，写工具
  审批人不能是请求人。
- 模板沉淀会快照试用员工实际绑定的 Skill、知识空间、MCP、模型和知识策略。
- 自定义模板创建员工默认进入 TRIAL，继承资源并评测通过后才转为 ACTIVE。
- 员工草案在 DRAFT 状态可编辑；关键状态转换使用数据库行锁。
- 草案创建、编辑、评审、重开、试用、评测、发布和回滚均落不可变版本快照，
  页面可查看修订时间线和操作人。
- 版本历史支持逐字段对比；DRAFT 草案可回退名称、能力、意图、Skill 和工具白名单，
  回退本身也会生成新快照，不删除历史版本。
- 草案和模板拒绝原因由后端强制校验，不能通过绕过前端提交空原因。
- 模板型草案试用会应用草案修改后的能力、意图、Skill 和工具白名单。
- 草案与模板员工的评测、激活共用精确资源校验；发布前用 SHA-256 指纹复验资源，
  评测后删除或替换 Skill、知识空间、MCP、工具会阻止上线并要求重新评测。
- 员工名称、工具、模型、知识、Skill 和 MCP 可通过单个原子配置接口保存；
  任一绑定校验失败会整体回滚，不会留下半套配置。
- ACTIVE 员工的资源或 Skill/MCP 定义发生变化后自动回到 TRIAL，停用员工重新启用
  也必须重新评测；生产环境从内置模板创建员工同样从 TRIAL 开始。
- 知识绑定、MCP 审批单和事故单执行资源级租户校验；主管必须同租户、ACTIVE，
  且具备任务拆解协调能力。
- 主管任务重新检查会重新路由 PENDING 子任务；创建缺失员工后能力缺口可自动消除。
  执行使用原子 QUEUED 抢占，重复提交不会重复派发。
- 模板发布前验证必需 Skill、知识空间、MCP 和工具；发布后资源失效时拒绝克隆。
- 并发创建 Skill、员工、知识空间时唯一键冲突稳定返回 409；重复资源绑定返回 422。
- 自定义模板支持不可变修订历史、拒绝/停用后的重新打开和再次批准发布。

## 多租户、状态机与模板治理

- 多租户身份支持 OIDC `business_units` 声明；开发模式使用
  `X-Business-Unit-Id` / `X-Business-Units`。非开发环境拒绝 `APP_AUTH_MODE=dev`，
  且 OIDC 必须同时配置 issuer 和 audience，缺失时服务拒绝启动。
- 开发环境提供客服坐席、客服主管、知识运营、业务经理、审计员、平台管理员
  六种测试身份，并可在“主要演示单元 / 隔离验真单元”之间切换业务上下文。
- Mock Business 作为工单同步、电商发布和物流查询默认 Provider；隔离验真单元
  已写入 120 条工单、30 份知识和 60 条评测题，评测 60/60 通过。
- 全局 API 查询守卫阻止跨租户 `business_unit_id`，全局 JSON 写请求守卫校验请求体租户；
  两者只覆盖显式声明的租户，资源归属由路由和服务层单独校验。
- 工单、知识文档/版本、客服会话、电商资源、AgentRun Trace 和工具调用均按资源
  `business_unit_id` 校验，越权统一返回 `403 BUSINESS_UNIT_ACCESS_DENIED`；
  列表与指标未传租户时回落到当前身份的主业务单元。
- 工单幂等键重放前先校验已有工单归属，避免跨租户通过 409 响应泄露工单 ID。
- 工单状态迁移走显式白名单：自动化流程不能离开终态，客服轮次和人工操作显式
  放行重开；非法跳转返回 `INVALID_WORKFLOW_TRANSITION`，每次迁移保留记录。
- 多租户实现、攻击复现和回归测试见
  [多租户隔离设计](tenant-isolation.md)。
- 模板克隆保存模板 ID、版本和必需资源快照；激活时按具体 Skill、知识空间、
  MCP 工具集合校验，不只看数量。
- 用户追加知识不会覆盖模板必需知识；模板 DRAFT 可编辑并生成新修订。
- 生产环境强制独立评审人，创建草案或模板的账号不能自行批准。
- 生产环境手工创建员工必须从 TRIAL 开始。

## 身份、角色与能力

- 角色到能力只由服务端 `ticket_agent.identity.policy` 维护，前端不再复制角色权限表。
- `GET /api/v1/me` 返回当前角色、能力清单、业务单元、策略版本和演示数据恢复可用性。
- 后端路由守卫统一按能力判断；前端按同一清单渲染菜单、路由和按钮，越权页面显示 403，
  只读角色不出现审批、接管、目录维护、上架和演示重置等写操作入口。
- 员工相关读写分为三个能力：`employees.directory` 是运行目录读取（员工列表、
  修订和能力快照），对坐席、主管、知识运营和管理员开放，供对话、电商分派和员工
  快照使用；`employees.view` 是员工管理台（模板、草案、路由规则、路由评测和决策）
  的读取，只对知识运营和管理员开放；`employees.write` 守卫新建、编辑、评审、发布、
  回滚和试用。业务经理和审计员没有员工目录读取能力，运行看板只通过
  `GET /api/v1/metrics/workforce` 读取聚合在岗人数，不暴露员工配置明细。
  普通坐席的对话仍由服务入口员工池和服务端自动路由完成。
- 开发演示提供六种身份，审计员和业务经理默认只读；未知 OIDC 角色按 requester 处理，
  不会继承管理员能力。

- 员工页面内部提供员工、模板、规程、连接、路由、主管编排和发布导航；
  客服页面内部提供“客户服务、工作台、运营看板、待审批操作、执行异常”导航。
- 客服运营三页职责固定：运营看板只展示指标、趋势、告警和待接管队列；
  待审批操作处理尚未执行的外部写操作；执行异常处理失败或结果不确定的操作。
  客户服务测试表单和完整会话列表不再混入运营看板。
- 页头提供“5 步技术演示”引导，从抽屉内的技术主线、员工上岗、真实 MCP、Agent 对话
  走到 ToolCall 与 Trace；演示视角可直接在页头“切换视角”下拉切换，不必进入
  演示引导，业务单元切换仍放在 5 步演示设置中。
- 客服沙盒明确标记演示入口，并显示“数字员工已完成、处理结论、下一步”的中文解释。
- 客服沙盒边界统一使用“企业消息渠道与外部业务系统消息渠道”，不再把通用客服
  绑定到电商平台；聊天和人工回复都明确只写入本地演示会话。
- 客服日常处理界面随场景切换文案：企业服务台使用制度、账号、IT、内部流程和敏感
  操作术语；电商客服使用商品、物流、售后和退款审批术语。平台管理页面则明确显示
  `Skill（岗位规程）` 和 `MCP（业务连接）`，并提供员工能力配置直达入口。
- 企业服务台和电商客服分别从侧边栏“企业服务台 Agent”和“电商运营复用”进入，客服
  页面内不再提供业务类型切换器；避免把真实坐席渠道误做成手动测试开关。
- 企业服务台对话提供跨岗位快捷问题（仓库文档、入职材料、账号被锁、权限边界），
  对话窗口标题显示本次由哪名数字员工处理并可点开能力快照，避免演示被理解成
  单一研发机器人。
- 页头身份标签可直接打开角色菜单并切换到对应角色首页，切换后显示“已切换为…”提示；
  业务单元切换收进“5 步演示”的演示设置。正式环境由登录身份和所属业务单元自动确定。
- 客服聊天明确区分“操作身份、业务场景、对话数字员工”；聊天会话按
  `业务单元 + 操作身份 + 业务场景` 隔离，切换身份后不会恢复上一位身份的对话。
- 五步演示、能力边界、知识示例、模型外部集成和员工系统连接使用跨场景文案；
  商品、物流、售后、退款等术语只保留在电商内容、电商客服和电商岗位模板中。
- 平台知识库演示数据同时包含企业服务、客户服务 SOP、IT 与权限、财务、HR 和
  电商渠道知识；知识空间默认只显示当前可用且排除自动化测试域。
- 自动路由结果主表使用员工姓名、中文原因、触发来源和置信度；历史英文原因会
  自动转换，测试员工和停用员工的规则默认不进入“当前生效”视图。
- 知识评测案例按业务单元、知识空间、数字员工、数据集和规范化问题去重；相同问题
  再次创建会复用原案例。评测页默认只显示当前启用案例，停用空间会联动停用关联
  案例；页面可按调参集/留出集切换，留出集案例显示“已冻结”，仅提供“恢复启用”。
- 内部工单默认排除已关闭测试工单；分类和目标团队使用中文。E2E 创建的工单自动关闭，
  演示恢复脚本批量归档历史测试前缀，当前默认队列只保留 5 张标准演示工单。
- 员工名单增加“上岗检查”，直接区分可以上岗、待检查、检查未通过和已停用。
- 页面明确标注“已运行 / 沙盒或演示 / 未接入生产”，避免把场景数据误认为生产接入。
- 数字员工能力拆成员工、模板、Skill、MCP、路由、主管任务和草案发布七个二级页面；
  平台菜单和员工页顶部均明确显示 Skill、MCP，不再只使用容易误解的业务别名。
- 管理员可从缺口卡片手动套用模板创建员工；创建前必须填写名称并确认，不会自动上线。
- Nginx 使用 Docker DNS 动态解析 API；重建 API 后无需同步重启 Web，避免旧 IP 造成 502。
- 千问返回短工具名或把参数字段拼进工具 ID 时，只对唯一匹配的已授权工具做严格恢复，
  参数缺失仍走独立受限提取，禁止猜测订单号或金额。
- 证据不足时任务进入 `NEEDS_REVIEW`，不会伪造订单、物流或审批结果。
- 员工中心可绑定 MCP 连接器，并配置允许工具和写权限开关。
- 客服沙盒按品类选择商品，反馈自动归属员工已授权的知识空间。
- 客服会话通过 Conversation Turn Runtime 持久化每一轮执行，支持多轮上下文、
  员工配置快照、知识引用、ToolCall、Trace 和单会话工单复用。
- 客服会话支持接管、释放和乐观锁冲突保护。
- 客服坐席支持在线心跳、当前会话和在线数量统计。
- P0/P1 会话支持主管告警、确认和强制改派。
